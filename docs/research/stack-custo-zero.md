# Stack de custo zero pra um PWA com push agendado, arquivos e acesso por link

Pesquisa do ticket [03-stack-custo-zero](../../.scratch/wayfinder-v1/issues/03-stack-custo-zero.md). Todas as fontes são páginas oficiais de preço ou documentação, acessadas em **03/09/2026**, salvo indicação contrária. Onde a fonte oficial não responde, a afirmação está marcada como **não confirmado** e listada no fim.

Cenário avaliado: 15 pessoas (maioria iPhone), um dev, milhares de linhas no banco, dezenas de MB em Word/PDF, push web (VAPID) com um lembrete agendado na véspera às 18h (America/Sao_Paulo = 21:00 UTC; o Brasil não tem horário de verão desde 2019), login por link de convite sem e-mail nem senha.

## Resumo executivo

1. Só **Cloudflare** entrega tudo (hospedagem, banco relacional, arquivos, função agendada por minuto, funções server-side) a US$ 0 **sem cartão e sem "dormir"**, desde que os arquivos fiquem em KV (ou D1) em vez de R2, que exige cartão.
2. **Supabase Free** é o backend mais completo (Postgres + Storage + Edge Functions + pg_cron com granularidade de segundos), mas o projeto **pausa após 1 semana sem atividade**: um lembrete agendado num projeto pausado simplesmente não sai.
3. **Firebase Spark** não roda Cloud Functions nem Cloud Storage (Storage exige Blaze desde 03/02/2026); o push agendado só existe no Blaze, que é US$ 0 dentro das cotas mas **exige conta de faturamento**. Firestore não é relacional.
4. **Vercel Hobby + Neon** funciona a custo zero e permite uso não comercial (ministério de igreja cabe), mas o cron do Hobby é **1x/dia com precisão de ±59 min**: "18h" vira "entre 18h e 19h".
5. **Netlify Free** tem 300 créditos/mês com **teto duro**; cada deploy de produção custa 15 créditos (máximo 20 deploys/mês, e o site é pausado quando acaba). Ruim pra um dev iterando.
6. **Fly.io** não tem free tier: trial de 7 dias/2 h de VM, cartão obrigatório, menor máquina US$ 2,02/mês. Descartado.
7. Web Push em iOS exige 16.4+, app adicionado à tela inicial e permissão pedida num gesto do usuário; é padrão W3C (VAPID), logo qualquer backend serve.
8. Bibliotecas de Web Push em Web Crypto puro (sem Node `crypto`) rodam em Workers, Deno e Bun; a única atenção é o teto de **10 ms de CPU por invocação** no Workers Free, que pede fan-out ao enviar pra muitos dispositivos.
9. Front: **Vite + React SPA** e **SvelteKit adapter-static (modo SPA)** são os que casam melhor com PWA (vite-plugin-pwa/Workbox) e com Capacitor (`webDir` estático com `index.html`). Next.js `output: 'export'` funciona, mas o próprio guia PWA do Next depende de Server Actions, que o export não suporta. Astro é pra sites de conteúdo, não pra app com estado.
10. Recomendação: **Stack A = Cloudflare Workers (static assets + API) + D1 + KV + Cron Triggers, front Vite+React ou SvelteKit**. Plano B: Supabase como backend com ping de keep-alive. Plano C: Vercel + Neon aceitando cron impreciso.

## Requisitos transversais

**Web Push no iPhone.** iOS/iPadOS 16.4+, app adicionado à tela inicial com manifest `display: standalone` ou `fullscreen`, permissão pedida "in response to direct user interaction", padrão W3C (Push API + Notifications + Service Worker), Badging API disponível ([WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), acessado 03/09/2026). Isso confirma a premissa de onboarding (adicionar à tela inicial e permitir notificações) e torna o backend indiferente: qualquer serviço que assine JWT VAPID e criptografe o payload serve.

**Envio agendado.** O lembrete "véspera às 18h" precisa de um gatilho por horário fora do dispositivo. Os únicos free tiers com gatilho de minuto em minuto são Cloudflare Cron Triggers e Supabase pg_cron. Vercel Hobby dá 1x/dia com janela de 1 h. GitHub Actions `schedule` (grátis em repo público, 2 000 min/mês em privado) serve como plano de contingência, mas "can be delayed during periods of high loads" e é desabilitado após 60 dias sem atividade em repo público ([events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows), [billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)).

**Auth por link de convite.** Nenhum provedor oferece "link de convite sem e-mail" pronto. Dois desenhos viáveis:

- *Token próprio*: o Ministro gera um link com token de uso único; a função server-side valida, cria um registro `dispositivo` e devolve um JWT de longa duração guardado em `localStorage`/IndexedDB do PWA. Não depende de auth de provedor; funciona igual em Cloudflare, Vercel e Supabase (Edge Function).
- *Supabase anonymous sign-in + vínculo*: o dispositivo faz `signInAnonymously()`, a Edge Function valida o token de convite e grava `auth.uid()` na tabela de Membros; RLS passa a usar `auth.uid()`. Ganha RLS de graça, mas a sessão anônima é por dispositivo (um Membro com dois aparelhos vira dois `uid`s vinculados ao mesmo Membro) e há rate limit de 30 sign-ins/h por IP.

Firebase teria o mesmo desenho via anonymous auth, mas custom tokens exigem Admin SDK num servidor (Blaze).

## Frameworks vs critérios

Critérios: (a) qualidade de PWA (service worker, manifest, atualização de versão), (b) compatibilidade com Capacitor, (c) simplicidade pra um dev.

O que o Capacitor exige, pela doc oficial: `webDir` é "the directory of your compiled web assets. This directory should contain the final `index.html` of your app" ([config](https://capacitorjs.com/docs/config)); o fluxo é buildar o app web e `npx cap sync` copia o bundle pros projetos nativos ([workflow](https://capacitorjs.com/docs/basics/workflow)); o `index.html` precisa ter `<head>` ([getting started](https://capacitorjs.com/docs/getting-started)); `server.url` "is not intended for use in production". Ou seja: saída estática, sem SSR em runtime. Nenhuma doc oficial do Capacitor trata de Next.js ou SvelteKit especificamente; os guias existentes são de terceiros.

## Combinações recomendadas

### Stack A (recomendada): tudo em Cloudflare Workers Free

- **Front**: Vite + React (ou SvelteKit adapter-static em modo SPA) com vite-plugin-pwa em `injectManifest`, servido como Workers Static Assets (grátis e ilimitado, `not_found_handling = "single-page-application"`).
- **API**: o mesmo Worker, rotas `/api/*` via `run_worker_first`.
- **Banco**: D1 (SQLite). 15 pessoas × milhares de linhas cabem em 500 MB com folga enorme.
- **Arquivos**: KV (valor até 25 MiB, 1 GB total). Word/PDF de sequência costumam ter < 1 MB. Se um dia precisar de R2, é adicionar cartão, não migrar stack.
- **Push agendado**: Cron Trigger `0 21 * * *` (18h BRT) ou `* * * * *` lendo uma tabela `lembretes_pendentes`. Push pontual ("você foi escalado") sai direto da rota HTTP.
- **Auth**: token de convite → JWT HS256 assinado com Web Crypto, dispositivo registrado em D1.
- **Custo**: US$ 0/mês, sem cartão. Domínio `*.workers.dev` grátis.
- **Riscos**: (1) **10 ms de CPU** por invocação, inclusive cron: cada envio de push faz ECDH + HKDF + AES-GCM + assinatura ECDSA; pra 15 dispositivos é provável caber, mas não confirmei com medição. Desenho defensivo desde o início: o cron enfileira (Queues, 10 k ops/dia grátis) ou faz `fetch` pra si mesmo em lotes pequenos, cada lote com seus próprios 10 ms. (2) Cron é best-effort ("underutilized machines"): esperar minutos de atraso, não segundos. (3) D1 é SQLite, não Postgres; sem RLS, toda autorização fica no código do Worker. (4) 1 000 escritas/dia em KV: várias versões de arquivo por dia cabem, upload em massa não.
- **O que quebra primeiro com 50 pessoas**: nada de cota (100 k req/dia = 2 000 req/pessoa/dia). O que aperta é o mesmo teto de 10 ms: enviar 50 pushes numa única invocação certamente estoura, então o fan-out deixa de ser opcional. O plano Workers Paid (US$ 5/mês) sobe pra 30 s de CPU se um dia for preciso.

### Stack B: Supabase Free como backend, front estático em Cloudflare

- **Front**: igual à Stack A, hospedado em Workers Static Assets ou Pages.
- **Backend**: Supabase Free: Postgres, Storage (1 GB, 50 MB/arquivo), Edge Functions (Deno), pg_cron + pg_net chamando uma Edge Function `enviar-lembretes` às 21:00 UTC.
- **Auth**: anonymous sign-in + vínculo ao Membro via Edge Function, com RLS baseado em `auth.uid()`.
- **Custo**: US$ 0/mês. Cartão não é citado como exigência (não confirmado).
- **Riscos**: (1) **Pausa após 1 semana** de baixa atividade: numa semana sem culto ou em férias, o projeto pausa e o lembrete agendado não sai; a restauração é manual no dashboard. Mitigação: ping diário externo (GitHub Actions ou um Cron Trigger da Cloudflare batendo na REST API), que é gambiarra mas custa zero. Não confirmei se a atividade do próprio pg_cron conta como "user database activity". (2) Só 2 projetos ativos: dev e prod ocupam a cota inteira. (3) Web Push VAPID no Deno depende de lib Web Crypto de terceiros; o exemplo oficial só cobre Expo/FCM. (4) Sessões anônimas são por dispositivo; dois aparelhos do mesmo Membro precisam de vínculo explícito.
- **O que quebra primeiro com 50 pessoas**: nada de cota (500 MB de banco, 1 GB de arquivos, 500 k invocações). Continua sendo a pausa por inatividade e o limite de 2 projetos. Pro é US$ 25/mês, o maior salto entre as stacks.

### Stack C: Vercel Hobby + Neon Free + Vercel Blob

- **Front**: Vite + React ou SvelteKit servido pela Vercel; funções em `/api`.
- **Banco**: Neon Free (0,5 GB, scale-to-zero em 5 min: primeira query após ociosidade paga cold start).
- **Arquivos**: Vercel Blob (grátis dentro dos limites do Hobby).
- **Push agendado**: Vercel Cron 1x/dia, **janela de ±59 min**. Ou seja, o lembrete das 18h chega entre 18h e 19h. Não há segundo gatilho no Hobby pra corrigir isso; aceitar a imprecisão ou usar GitHub Actions como gatilho externo.
- **Custo**: US$ 0/mês, sem cartão. Uso não comercial: um ministério de igreja sem doações pelo app está dentro da regra; pedir doações no app o tira da regra.
- **Riscos**: (1) precisão do cron; (2) estourar qualquer cota do Hobby bloqueia o recurso por 30 dias; (3) Neon suspende compute até o mês seguinte se passar de 100 CU-h.
- **O que quebra primeiro com 50 pessoas**: continua sendo a precisão do cron (UX, não cota). Pro da Vercel é US$ 20/mês.

### Descartados

- **Firebase**: Spark não roda Functions nem Storage; Blaze é US$ 0 nas cotas mas exige conta de faturamento; Firestore não é relacional. Só faria sentido se o push nativo via Capacitor + FCM virasse prioridade, e mesmo assim FCM aceita ser chamado de qualquer backend.
- **Netlify**: 300 créditos/mês com teto duro e 15 créditos por deploy de produção; um dev fazendo deploy diário estoura em 20 dias e o site cai.
- **Fly.io**: não tem free tier.

## O que não confirmei

1. **Supabase exige cartão no Free?** Nem a página de preço nem a doc de billing dizem; o fluxo de cadastro sugere que não, mas não verifiquei criando conta.
2. **Usuários anônimos do Supabase contam como MAU?** A página de preço lista "anonymous sign-ins" como incluído em todos os planos, mas não diz se entram nos 50 000 MAU. Irrelevante pra 15 pessoas.
3. **Atividade do pg_cron evita a pausa do Supabase?** A doc fala em "user database activity" e "a few user requests to the database each day"; não define se jobs internos contam.
4. **R2 exige cartão**: só fontes da comunidade Cloudflare afirmam que o diálogo de cartão é obrigatório ao ativar R2 ([community](https://community.cloudflare.com/t/why-using-r2-free-tier-involves-giving-card-info/945179)); a doc oficial só diz "complete the checkout flow to add an R2 subscription" ([get started](https://developers.cloudflare.com/r2/get-started/)).
5. **Atraso real dos Cron Triggers no Workers Free**: a doc só diz que rodam em "underutilized machines"; não há SLA nem número.
6. **10 ms de CPU bastam pra N pushes?** Não medi. Precisa de um spike (é o primeiro protótipo técnico a fazer se a Stack A for escolhida).
7. **Neon pg_cron no Free**: a doc não restringe por plano, mas exige compute ativo, e o Free não desativa scale-to-zero; tratei como inviável por dedução.
8. **Compatibilidade das libs de Web Push com Deno (Supabase Edge)**: baseada no README de `@block65/webcrypto-web-push`, não em teste.
9. **Cotas incluídas do Vercel Blob no Hobby**: deduzidas do exemplo de preço da própria doc (5 GB, 100 k ops simples, 10 k avançadas, 100 GB); a tabela do Hobby na doc vem com os números em branco no HTML servido.
10. **Netlify Scheduled Functions**: intervalo mínimo não declarado explicitamente (extensões `@hourly` etc. são listadas; cron de minuto não é vedado nem confirmado).
11. **Guia oficial Capacitor para Next.js ou SvelteKit**: não existe; a compatibilidade decorre da exigência genérica de `webDir` estático com `index.html`.
